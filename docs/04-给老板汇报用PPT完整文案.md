## 02｜一句话结论

### 页面标题

我们建议建设一套“AI 内容工业化平台”

### 核心结论

不是用一句提示词直接生成视频，而是把公司影视动漫生产经验沉淀为一套结构化、可审核、可复用的 AI 生产流程。

### 页面重点

1. 第一阶段以小说文本为主要输入。
2. 通过 AI 完成剧情分析、剧本化改写、资产卡生成和 Storyboard。
3. 再以镜头为单位生成关键帧、视频片段和成片预览。
4. 每个关键节点都保留人工确认、版本管理和资产沉淀。

### 视觉建议

用“四段式大卡片”展示：

| 输入 | 中间层 | 生成 | 沉淀 |
|---|---|---|---|
| 小说文本 | 剧本 / 资产卡 / Storyboard | 图像 / 视频 / 声音 | 项目资产库 |

### 演讲备注

核心观点是：AI 视频生成真正可控的关键，不在最后生成视频，而在视频生成之前的结构化准备。

## 03｜行业背景：AI 正在重塑内容生产

### 页面标题

AI 正在进入影视动漫内容生产的核心链路

### 页面文案

大语言模型、图像生成、视频生成、语音合成和自动剪辑能力正在快速成熟，内容生产正在从“纯人工经验驱动”转向“人工创意 + AI 辅助生产 + 平台化管理”。

### 关键趋势

- 文本大模型：可参与小说理解、剧情拆解、剧本改写。
- 图像模型：可生成角色、场景、风格图和关键帧。
- 视频模型：可生成镜头级视频片段。
- 语音模型：可生成角色配音、旁白和声音测试。
- 自动剪辑：可完成字幕、拼接、预览和基础后期。

### 视觉建议

- 左侧：传统影视流程图。
- 右侧：AI 能力图谱。
- 中间用箭头表示“AI 能力进入生产链路”。

### 演讲备注

AI 不是只影响某一个环节，而是正在覆盖从文本理解、视觉设定、分镜设计到视频生成和后期的多个环节。

## 04｜传统生产痛点

### 页面标题

当前内容生产链路存在明显效率瓶颈

### 页面文案

传统影视、动漫、短剧和漫剧生产流程长、协作岗位多、经验依赖强。在实际项目中，前期拆解、设定确认、分镜沟通和素材复用都存在明显成本。

### 痛点列表

1. 前期内容拆解周期长。
2. 编剧、美术、导演、后期之间沟通成本高。
3. 角色、场景、风格设定容易反复修改。
4. 分镜、画面和视频生成缺少统一结构。
5. 多工具割裂，项目数据分散。
6. 角色、场景、道具、提示词难以复用。
7. 项目经验依赖个人，难以沉淀为标准流程。

### 视觉建议

- 用“断裂流水线”表达：剧本、角色、美术、分镜、生成、后期之间断开。
- 每个断点标注“沟通成本”“重复修改”“不可复用”“难追溯”。

### 演讲备注

这些问题并不是单个岗位的问题，而是整个生产链路缺少统一结构和资产沉淀机制。

## 05｜为什么不能直接用一句提示词生成视频

### 页面标题

单句提示词生成视频，不适合工业化内容生产

### 页面文案

如果直接用一句提示词生成视频，短期可以演示效果，但很难支撑连续叙事、多镜头一致性和可修改的生产流程。

### 主要问题

| 问题 | 表现 |
|---|---|
| 叙事不稳定 | 镜头之间缺少连贯剧情 |
| 角色不一致 | 人脸、服装、年龄、气质变化 |
| 场景漂移 | 同一空间在不同镜头中变化 |
| 风格不统一 | 色彩、光影、材质不连续 |
| 镜头随机 | 景别、机位、运镜不可控 |
| 修改困难 | 不知道该改提示词、图像还是视频 |
| 经验难沉淀 | 成功经验停留在个人提示词里 |

### 视觉建议

- 左侧：一个“单句 Prompt”直接指向混乱视频画面。
- 右侧：结构化资产 + Storyboard 指向稳定视频镜头。
- 用红色叉号标注“不适合工业化”，用绿色对勾标注“适合生产闭环”。

### 演讲备注

一句提示词可以做 Demo，但不能做稳定生产。真正要落地，需要把提示词之前的剧情、人物、场景、风格和镜头全部结构化。

## 06｜我们的解决方案：先结构化，再生成

### 页面标题

平台核心思路：先把内容生产结构化，再调用 AI 生成

### 页面文案

平台在视频生成之前，先完成小说理解、剧本化改写、角色卡、场景卡、风格卡、道具卡、声音卡和 AI Storyboard，用这些中间层约束后续图像与视频生成。

### 关键路径

小说文本 → AI 剧情分析 → AI 剧本化改写 → 人工确认 → 资产卡 → AI Storyboard → 关键帧 / 参考图 → 镜头级视频 → 后期合成 → 成片导出 → 资产沉淀

### 视觉建议

- 页面中央放一条横向生产流水线。
- 用不同颜色区分：文本层、资产层、镜头层、生成层、沉淀层。
- 每个节点用图标表示：书本、剧本、角色、场景、分镜、视频、文件库。

### 演讲备注

我们不是让 AI 替代整个制作团队，而是让 AI 在标准流程中生成初稿、候选结果和可复用资产，再由人确认。

### 演讲备注

## 09｜核心机制：AI 生成 + 人工确认

### 页面标题

关键节点必须保留人工确认和版本保存

### 页面文案

平台不追求全自动黑盒生成，而是采用“AI 生成初稿 / 候选结果，人工审核、修改、确认，再进入下一环节”的机制。

### 机制说明

| 环节 | AI 负责 | 人负责 | 系统负责 |
|---|---|---|---|
| 小说分析 | 生成结构化分析 | 判断是否准确 | 保存版本 |
| 剧本改写 | 生成剧本初稿 | 修改剧情和台词 | 记录正式版本 |
| 资产卡 | 生成设定和提示词 | 调整形象和风格 | 绑定后续任务 |
| Storyboard | 拆分镜头 | 确认镜头节奏 | 创建镜头任务 |
| 视频生成 | 生成候选片段 | 审核和重生成 | 记录参数和成本 |

### 视觉建议

- 做成“三段循环图”：AI 生成 → 人工确认 → 版本保存 → 继续流转。
- 循环中心写“可控生产”。

### 演讲备注

这是平台可落地的关键。AI 不是一次性替代人，而是在每个环节提高初稿效率，人保留最终判断权。

## 10｜核心中间层：资产卡 + Storyboard

### 页面标题

视频生成前，必须先建立六类核心中间层

### 页面文案

角色、场景、风格、道具、声音和 Storyboard 是平台控制一致性的关键。

### 六类中间层

| 中间层 | 解决的问题 |
|---|---|
| AI 角色卡 | 控制人物外形、服装、表情、动作、声音 |
| AI 场景卡 | 控制空间布局、光线、天气、不可变元素 |
| AI 风格卡 | 控制作品整体画风、色彩、光影和质感 |
| AI 道具卡 | 控制关键物件的外观和叙事功能 |
| AI 声音卡 | 控制角色声线、语速、语气和环境声 |
| AI Storyboard | 控制镜头编号、景别、机位、运镜和时长 |

### 视觉建议

- 中央放“AI Storyboard”作为核心枢纽。
- 周围环绕角色卡、场景卡、风格卡、道具卡、声音卡。
- 用线连接到“镜头级生成任务”。

### 演讲备注

这几个中间层决定了后续视频生成是否可控，也是未来资产复用和规模化生产的基础。

## 11｜镜头级生成逻辑

### 页面标题

平台不让用户手写单句提示词，而是自动组装镜头级生成任务

### 页面文案

每个镜头的生成任务由 Storyboard 镜头说明、角色卡、场景卡、风格卡、道具卡、声音卡、提示词、参考图和模型参数共同组成。

### 生成任务公式

镜头级生成任务 = Storyboard 镜头说明 + 角色卡约束 + 场景卡约束 + 风格卡约束 + 道具卡约束 + 声音卡约束 + 正向提示词 + 负向提示词 + 参考图 / 参考视频 + 模型参数

### 视觉建议

- 用“配方图”表达：多个材料进入一个生成引擎，输出镜头视频。
- 材料卡片包括角色、场景、风格、道具、声音、提示词、参数。

### 演讲备注

这样做的好处是，把提示词能力从个人经验变成系统能力，降低使用门槛，也便于复盘和复用。

## 13｜第一阶段建设范围

### 页面标题

第一阶段先做最小可用闭环，不做大而全

### 页面文案

第一阶段目标是完成从小说文本到视频片段和简单成片预览的可演示闭环，验证流程、模型效果、成本和团队协作方式。

### 第一阶段覆盖

- 项目创建
- 小说文本输入
- AI 小说分析
- 剧本化改写
- 人工审核与版本保存
- 角色 / 场景 / 风格卡生成
- Storyboard 镜头卡生成
- 镜头级提示词生成
- 关键帧 / 参考图生成
- 视频片段生成
- 人工审核与重生成
- 简单剪辑预览
- 项目资产保存

### 第一阶段不重点做

- 完整多人协作
- 复杂权限体系
- 大规模资产市场
- 完整商业级后期
- 复杂 Agent 自主编排

### 视觉建议

- 左侧：P0 必做闭环。
- 右侧：后续阶段功能。
- 用“聚焦第一阶段”的聚光灯效果。

### 演讲备注

第一阶段要控制范围，把验证闭环做扎实，避免一开始就做成周期长、风险高的大平台。

## 16｜技术架构建议

### 页面标题

采用轻量、稳定、可扩展的技术架构

### 技术架构

| 层级 | 建议方案 |
|---|---|
| 前端 | Next.js / React |
| 后端 | FastAPI / Node.js |
| 数据库 | PostgreSQL |
| 对象存储 | MinIO / OSS / COS |
| 任务队列 | Redis + Celery / BullMQ |
| 模型适配层 | 统一接入文本、图像、视频、语音模型 |
| 视频处理 | FFmpeg |
| 向量检索 | pgvector / Milvus |
| 部署 | Docker + 云服务器 |

### 架构原则

1. 工作流优先，复杂 Agent 框架后置。
2. 模型可替换，生产数据和资产保留。
3. 数据结构先行，界面逐步完善。
4. 关键节点保留人工审核。

### 视觉建议

- 分层架构图：前端层、业务层、任务层、模型层、存储层。
- 模型层用多个模型图标表示可替换。

### 演讲备注

我们不建议第一阶段上来就做复杂 Agent 系统，而是先用确定性工作流和模型适配层把核心流程跑通。

## 17｜模型能力需求

### 页面标题

项目推进的核心前提：可稳定调用大模型能力

### 模型类型

| 模型类型 | 用途 | 优先级 |
|---|---|---|
| 文本大模型 | 小说理解、剧情拆解、剧本改写、资产卡、Storyboard、提示词 | 最高 |
| 图像生成模型 | 角色图、场景图、风格图、关键帧、首尾帧 | 最高 |
| 视频生成模型 | 文生视频、图生视频、首帧/首尾帧视频 | 最高 |

### 视觉建议

- 文本、图像、视频三类模型用重点高亮。

### 演讲备注

没有稳定模型能力，平台闭环无法形成。第一阶段要优先确认文本、图像、视频三个核心模型的可用性。

## 20｜主要风险与应对

### 页面标题

风险可控，关键是分阶段和保留人工审核

### 风险应对表

| 风险 | 应对策略 |
|---|---|
| 平台目标过大 | 分阶段建设，先完成核心闭环 |
| 视频质量不稳定 | 多版本生成 + 人工审核 + 重生成 |
| 角色一致性不足 | 角色卡 + 参考图 + 提示词模板 |
| 场景漂移 | 场景卡 + 空间布局 + 不可变元素 |
| 画风不统一 | 风格卡 + 色彩规则 + 负向提示词 |
| 成本不可控 | 模型成本记录 + 任务级统计 |
| 模型变化快 | 模型适配层，底层模型可替换 |
| AI 结果不可直接用 | 关键节点人工确认和版本保存 |

### 视觉建议

- 用“风险仪表盘”形式。
- 每个风险用红黄绿状态标识。
- 应对策略用绿色对勾。

### 演讲备注

风险主要来自模型质量和范围失控。我们的方案用结构化流程、人工审核和分阶段推进来降低风险。

# 附录 C｜建议 PPT 版式模板

## C1. 标题页

- 大标题占 40%。
- 背景使用全屏视觉图。

- 左侧一句核心结论。
- 右侧一张概念图或对比图。

- 横向流程图为主。

- 控制表格文字密度。
- 每行保留关键词。
- 重要行用浅色底高亮。

## C5. 决策页

- 三个决策卡片。
- 每张卡片包含“事项、建议、下一步”。
- 最下方放明确结论。
