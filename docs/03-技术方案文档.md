# AI 内容工业化平台技术方案文档

## 1. 技术目标

本技术方案面向第一阶段核心闭环原型，目标是构建一套稳定、轻量、可扩展的 AI 内容生产系统，支持小说文本输入、AI 分析、剧本化改写、资产卡生成、AI Storyboard、镜头级图像/视频/语音生成、人工审核、简单预览和项目资产沉淀。

技术设计原则：工作流优先，复杂 Agent 框架后置；数据结构先行，模型可替换；长耗时任务异步化；所有生成结果可追踪、可版本化、可审核；先完成核心闭环，再扩展协同和平台化能力。

## 2. 推荐技术栈

为避免后续开发阶段出现技术路线分叉，第一阶段默认采用以下实施基线。其他同类技术可作为后续替换方案，但不作为第一版并行实现目标。

| 层级 | 推荐方案 | 说明 |
|---|---|---|
| 前端 | Next.js + React + TypeScript | 项目工作台、编辑器、资产管理、任务状态展示 |
| UI | Tailwind CSS + Ant Design | 快速构建后台管理型界面 |
| 后端 | FastAPI + Pydantic + SQLAlchemy | REST API、鉴权、工作流编排、任务创建 |
| 数据库 | PostgreSQL | 核心业务数据、版本、状态、审核记录 |
| 数据库迁移 | Alembic | 表结构版本管理 |
| 向量检索 | pgvector | 小说片段、资产、提示词和历史案例检索；Milvus 后续再评估 |
| 对象存储 | MinIO，兼容 S3 API | 图片、视频、音频、字幕和导出文件；生产可替换 OSS/COS/S3 |
| 任务队列 | Redis + Celery | 模型调用、视频生成、转码、合成等异步任务 |
| 视频处理 | FFmpeg | 转码、拼接、字幕合成、封面提取 |
| 模型适配 | Provider Adapter | 统一文本、图像、视频、语音模型调用 |
| 部署 | Docker / Docker Compose | 第一阶段快速部署，后续可迁移 Kubernetes |
| 监控 | Prometheus + Grafana / OpenTelemetry | API、任务、模型调用、成本和错误监控 |

## 3. 总体架构

系统由前端工作台、后端 API、工作流服务、异步任务队列、模型适配层、对象存储、数据库和视频处理服务组成。

前端负责创作者工作台、内容编辑、资产卡管理、Storyboard 管理、任务状态展示和结果审核。后端负责业务数据、访问控制、版本、审核、任务创建和工作流状态推进。异步 Worker 负责调用模型、处理文件、转码和合成。模型适配层封装不同文本、图像、视频和语音供应商。对象存储保存媒体文件，PostgreSQL 保存结构化数据。

## 4. 核心服务划分

### 4.1 Web Frontend

功能包括项目列表、项目工作台、小说输入、分析结果编辑、剧本编辑、资产卡管理、Storyboard 编辑、生成任务看板、视频预览和模型配置。

### 4.2 API Service

功能包括用户与访问控制、项目管理、文本管理、版本管理、资产管理、镜头管理、任务管理、审核记录、模型配置和成本记录。

### 4.3 Workflow Service

负责确定性工作流推进，例如小说分析完成后允许生成剧本，剧本确认后允许生成资产卡和 Storyboard，Storyboard 确认后允许创建镜头生成任务。

第一阶段建议采用状态机 + 任务模板，不引入过重的多 Agent 自主规划机制。

### 4.4 Worker Service

负责执行异步任务，包括文本分析、剧本生成、资产卡生成、提示词生成、图像生成、视频生成、语音生成、字幕生成、视频转码、视频拼接和结果回写。

### 4.5 Model Adapter Service

统一封装模型调用。对上提供统一接口，对下适配不同供应商。每次调用记录 provider、model、request、response 摘要、文件引用、耗时、token/时长、成本和错误。

### 4.6 Asset Service

管理图片、视频、音频、字幕、参考文件、生成结果和导出文件。文件实体保存在对象存储，数据库只保存元数据、URL、hash、类型、大小和关联关系。

## 5. 数据模型设计

### 5.1 核心表

1. users：用户信息。
2. projects：项目基础信息和生产状态。
3. novel_documents：小说文本、章节和输入片段。
4. analysis_versions：小说分析结果版本。
5. script_versions：剧本版本。
6. character_cards：角色卡。
7. scene_cards：场景卡。
8. style_cards：风格卡。
9. prop_cards：道具卡。
10. voice_cards：声音卡。
11. storyboard_shots：Storyboard 镜头卡。
12. generation_tasks：生成任务。
13. generation_results：生成结果。
14. review_records：审核记录。
15. media_assets：文件资产。
16. prompt_templates：提示词模板。
17. model_providers：模型供应商配置。
18. model_invocations：模型调用记录。
19. cost_records：成本记录。
20. export_versions：成片预览和导出版本。

### 5.2 关键字段建议

projects：id、name、type、genre、target_duration、aspect_ratio、language、style_direction、status、owner_id、created_at、updated_at。

analysis_versions：id、project_id、source_document_id、summary、plot_structure、characters、scenes、props、conflicts、emotion_curve、status、version_no、created_by、confirmed_at。

script_versions：id、project_id、analysis_version_id、episodes、scenes、dialogues、narrations、status、version_no、created_by、confirmed_at。

storyboard_shots：id、project_id、script_version_id、shot_no、episode_no、scene_no、description、shot_size、camera_angle、camera_movement、duration_seconds、characters、scene_card_id、style_card_id、prop_card_ids、dialogue、narration、sound_effects、positive_prompt、negative_prompt、status、sort_order。

generation_tasks：id、project_id、shot_id、task_type、input_mode、model_provider_id、model_name、parameters、status、priority、cost_estimate、started_at、finished_at、error_message。

generation_results：id、task_id、shot_id、media_asset_id、thumbnail_asset_id、prompt_snapshot、parameters_snapshot、status、review_status、score、failure_reason、is_confirmed。

media_assets：id、project_id、asset_type、file_name、storage_key、mime_type、size_bytes、duration_seconds、width、height、hash、source_type、created_by。

## 6. 工作流设计

### 6.1 第一阶段主流程

1. PROJECT_CREATED：创建项目。
2. NOVEL_UPLOADED：输入小说文本。
3. ANALYSIS_RUNNING：创建小说分析任务。
4. ANALYSIS_REVIEW：分析结果待审核。
5. ANALYSIS_CONFIRMED：确认分析结果。
6. SCRIPT_RUNNING：生成剧本版本。
7. SCRIPT_REVIEW：剧本待审核。
8. SCRIPT_CONFIRMED：确认剧本。
9. ASSET_RUNNING：生成资产卡。
10. ASSET_REVIEW：资产卡待审核。
11. ASSET_CONFIRMED：确认资产卡。
12. STORYBOARD_RUNNING：生成 Storyboard。
13. STORYBOARD_REVIEW：Storyboard 待审核。
14. STORYBOARD_CONFIRMED：确认镜头卡。
15. GENERATION_RUNNING：镜头生成任务执行。
16. GENERATION_REVIEW：生成结果待审核。
17. POST_PROCESSING：后期预览与拼接。
18. COMPLETED：完成预览或导出。

### 6.2 审核机制

每个关键对象均有版本状态和审核状态。AI 结果默认是候选版本，用户可编辑后保存为新版本。被确认的版本成为正式输入，下游任务只读取正式版本。退回版本保留历史，失败结果可进入失败案例库。

## 7. 模型适配层设计

### 7.1 统一接口

模型适配层建议提供以下能力：text.generate、text.extract_structured、image.generate、video.generate、audio.tts、audio.transcribe、embedding.create。

### 7.2 文本模型任务

文本模型用于小说分析、剧情拆解、剧本化改写、角色/场景/风格/道具/声音卡生成、Storyboard 拆分和提示词生成。要求支持结构化 JSON 输出、重试、超时、分段处理和输出校验。

### 7.3 图像模型任务

图像模型用于角色参考图、场景参考图、风格图、Storyboard 关键帧、首帧和尾帧。要求支持提示词、负向提示词、参考图、尺寸、种子、生成数量和结果回传。

### 7.4 视频模型任务

视频模型需抽象 input_mode，包括 text_to_video、image_to_video、first_frame_to_video、first_last_frame_to_video、reference_images_to_video、reference_video_to_video。不同供应商能力不同，前端应根据模型能力展示可用参数。

### 7.5 语音与字幕任务

语音模型用于角色 TTS、旁白和声音测试。字幕模型用于音频转写或基于台词生成字幕。第一阶段可优先支持基于剧本台词直接生成字幕，语音转写作为增强能力。

## 8. API 设计建议

### 8.1 项目 API

POST /api/v1/projects：创建项目。
GET /api/v1/projects：项目列表。
GET /api/v1/projects/{id}：项目详情。
PATCH /api/v1/projects/{id}：更新项目。

### 8.2 小说与分析 API

POST /api/v1/projects/{id}/novels：保存小说文本。
POST /api/v1/projects/{id}/analysis-tasks：发起分析任务。
GET /api/v1/projects/{id}/analysis-versions：查看分析版本。
PATCH /api/v1/analysis-versions/{id}：编辑分析结果。
POST /api/v1/analysis-versions/{id}/confirm：确认分析版本。

### 8.3 剧本 API

POST /api/v1/projects/{id}/script-tasks：生成剧本。
GET /api/v1/projects/{id}/script-versions：剧本版本列表。
PATCH /api/v1/script-versions/{id}：编辑剧本。
POST /api/v1/script-versions/{id}/confirm：确认剧本。

### 8.4 资产 API

POST /api/v1/projects/{id}/asset-card-tasks：生成资产卡。
GET /api/v1/projects/{id}/asset-cards：资产卡列表。
PATCH /api/v1/asset-cards/{type}/{id}：编辑资产卡。
POST /api/v1/asset-cards/{type}/{id}/confirm：确认资产卡。
POST /api/v1/projects/{id}/media-assets：上传参考资产。

### 8.5 Storyboard 与生成 API

POST /api/v1/projects/{id}/storyboard-tasks：生成 Storyboard。
GET /api/v1/projects/{id}/shots：镜头列表。
PATCH /api/v1/shots/{id}：编辑镜头卡。
POST /api/v1/shots/{id}/confirm：确认镜头。
POST /api/v1/shots/{id}/generation-tasks：创建镜头生成任务。
GET /api/v1/generation-tasks/{id}：查看任务状态。
POST /api/v1/generation-results/{id}/review：审核生成结果。

### 8.6 后期 API

POST /api/v1/projects/{id}/preview-tasks：生成预览。
GET /api/v1/projects/{id}/exports：导出版本列表。
GET /api/v1/exports/{id}：导出详情。

## 9. 提示词与结构化输出

第一阶段建议为每类任务建立提示词模板：小说分析模板、剧本改写模板、角色卡模板、场景卡模板、风格卡模板、道具卡模板、声音卡模板、Storyboard 模板和镜头提示词模板。

所有关键文本模型任务应要求结构化输出，并在后端进行 schema 校验。校验失败时自动重试或进入人工修复。模板版本需要保存，生成结果记录 prompt_snapshot，确保可追溯。

## 10. 文件与媒体处理

上传和生成的媒体文件统一进入对象存储。后端生成缩略图、预览视频和元数据。视频生成完成后通过 FFmpeg 提取封面、转码为预览格式，并记录时长、分辨率、编码信息。预览拼接按已通过镜头的 sort_order 和 duration_seconds 生成。

## 11. 安全与访问控制

1. 模型 API Key 不进入前端，不写入日志明文。
2. 用户上传内容和生成内容按项目隔离。
3. 文件访问使用签名 URL 或后端代理。
4. 模型调用日志只保存必要摘要，避免泄露敏感正文。
5. 关键操作如确认版本、删除资产、导出成片需记录审计日志。
6. 后续阶段可增加轻量协作和项目级访问控制，但不按编剧、美术、导演、后期等传统岗位拆分系统角色。

## 12. 可观测性与成本控制

需要记录 API 请求耗时、任务队列等待时间、模型调用耗时、成功率、失败率、重试次数、生成成本、项目成本和用户操作日志。成本记录按 provider、model、task_type、project_id、shot_id 聚合，支持后续预算预警和模型效果对比。

## 13. 部署方案

第一阶段可采用 Docker Compose 部署：frontend、api、worker、postgres、redis、minio。模型供应商通过外部 API 接入。生产环境建议拆分对象存储和数据库到云服务托管，API 和 Worker 可按任务量横向扩展。

## 14. 可靠性设计

1. 异步任务需支持超时、重试、取消和失败原因记录。
2. 模型调用需支持 provider 降级和手动重跑。
3. Worker 幂等：同一任务重复执行不应产生错误状态覆盖。
4. 数据库写入与文件上传需保证引用一致性。
5. 长文本小说需分段处理并合并分析结果。
6. 生成任务结果先进入候选版本，避免自动覆盖正式版本。

## 15. 第一阶段实施计划

### 15.1 第 1-2 周：基础框架

完成项目初始化、数据库模型、项目管理、小说输入、文件上传、基础工作台和任务队列。

### 15.2 第 3-4 周：文本智能能力

接入文本大模型，完成小说分析、剧本化改写、结构化输出校验、版本管理和人工确认。

### 15.3 第 5-6 周：资产与 Storyboard

完成角色卡、场景卡、风格卡生成与编辑；完成 Storyboard 镜头卡生成、资产绑定和提示词生成。

### 15.4 第 7-8 周：图像与视频生成

接入图像和视频模型，完成关键帧、参考图、视频片段生成、多版本保存、任务日志和审核。

### 15.5 第 9-10 周：后期预览与验收

完成简单拼接预览、字幕基础能力、导出版本、成本统计、错误处理和试点项目验收。

## 16. 技术风险与应对

1. 模型结构化输出不稳定：使用 schema 校验、重试和人工修复。
2. 视频模型耗时长：异步队列、状态轮询、失败重试和通知机制。
3. 多模型能力差异大：使用 capability 配置驱动前端参数展示。
4. 文件体积大：对象存储、转码预览、分片上传和生命周期管理。
5. 成本不可控：任务级成本估算、调用记录和预算阈值。
6. 角色一致性不足：正式角色卡、参考图、种子、提示词模板和人工筛选。
7. 工作流复杂：第一阶段采用确定性状态机，后续再引入更复杂 Agent。

## 17. 后续扩展

后续可扩展轻量协作与项目访问控制、批量镜头生成、多模型 A/B 对比、资产库检索、失败案例学习、角色一致性检测、场景一致性检测、提示词模板市场、私有化部署、API 开放和工作流模板配置。
