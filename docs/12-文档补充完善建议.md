# AI 内容工业化平台｜文档补充完善建议

> 审阅日期：2026-06-04  
> 审阅范围：`docs` 下所有 Markdown 文档、UI 画板 README、UI 画板 HTML/PNG 的页面覆盖信息。  
> 目的：检查最近原型优化后，需求、技术、数据、接口、排期和任务拆解是否仍然对齐。

---

## 1. 总体结论

当前文档体系已经覆盖立项、PRD、技术方案、ERD、API、排期、任务拆解、架构图、页面结构、页面流转和 UI 画板，整体完整度较高，可以支撑第一阶段原型研发。

但最近 UI 原型已经发生明显演进，部分新增概念还没有反写到基线文档中。最需要优先补齐的是：

1. `项目画像确认 / Profile V1` 已经出现在 UI 画板和提示词模板矩阵中，但 PRD、ERD、API、任务拆解、排期、C4 和页面流转还没有把它作为正式流程节点和数据对象。
2. `创建项目` 原型从重表单变成“轻量项目容器 + 创作者意图”，但 PRD、API、排期和任务拆解仍按一次性填写类型、题材、时长、画幅、风格方向描述。
3. `后期预览与导出` 原型已经从“简单拼接”扩展为集/场/镜头/全片母版的组装视图，但 PRD、ERD、API、排期仍偏简单。
4. `任务中心、模型配置、提示词模板、系统设置/访问控制` 已经在 UI 画板中变成较完整页面，但 P0/P1 边界、接口优先级和任务拆解需要重新对齐。
5. `05-产品原型页面结构.md` 存在章节编号跳跃，`11-完整产品页面流转与缺失页面补全.md` 的页面清单少了 UI README 中的“项目画像确认”，需要整理。

### 2.2 同步创建项目的轻量化策略

现状：

- UI 画板的创建项目页强调“只建立项目容器”，内容来源、题材、语言、集数和视觉方向留到小说输入与画像确认阶段。
- PRD、API、排期、任务拆解仍要求创建项目时填写项目类型、题材、目标时长、画幅、语言、风格方向。
- `11-完整产品页面流转与缺失页面补全.md` 仍写“通过 step 表单依次填写项目基础、内容来源、成片目标、视觉方向和模型预设”。

建议：

1. 将创建项目字段拆成两类：
   - 必填：项目名称。
   - 可选创作意图：目标产物、初始风格偏好、备注。
2. 项目事实字段由 Profile V1 确认后回写或关联，不在创建阶段强制锁定。
3. `projects` 表保留 `metadata` 或 `creator_intent`，不要把未确认画像直接覆盖正式字段。
4. 创建项目接口请求示例改为轻量字段。

### 2.3 补齐 Source V1 / 源内容版本概念

现状：

- 原型强调“上传/录入 -> 解析内容 -> 确认源内容”，并出现 `Source V1`。
- ERD 目前有 `novel_documents` 和 `novel_chapters`，但没有明确源内容版本、解析异常、确认状态。
- API 有保存小说与上传小说文件，但缺少“确认源内容版本”和“解析问题修复”的专门接口。

建议：

1. 在 `novel_documents` 增加或明确字段：`version_no`、`status`、`parse_status`、`parse_issues`、`confirmed_by`、`confirmed_at`。
2. 或新增 `source_versions`，用于统一粘贴文本、上传文件、故事梗概扩展后的确认版本。
3. API 增加：

```text
POST /api/v1/novel-documents/{documentId}/parse
PATCH /api/v1/novel-chapters/{chapterId}
POST /api/v1/novel-documents/{documentId}/confirm
GET  /api/v1/novel-documents/{documentId}/parse-issues
```

### 2.4 后期预览需要从“简单拼接”升级为“组装与导出”

现状：

- 多份文档仍写“简单拼接预览”。
- UI 画板已经包含分集、场级、镜头片段、全片母版、素材包、字幕/配音/BGM/音效轨、导出设置抽屉。

建议第一阶段仍控制范围，但文档应明确后期模块的分层：

1. P0：按已确认镜头自动生成分集粗剪预览。
2. P0：导出本集 MP4 或素材包。
3. P1：场级/镜头级检查视图、字幕配音对齐、音频问题标记。
4. P1/P2：全片母版时间线、拖拽组装、外部精剪交付清单。

ERD 建议补充 `preview_versions` 或增强 `export_versions`：

```text
scope_type: shot / scene / episode / master
episode_no
scene_no
timeline_snapshot
subtitle_asset_id
audio_track_asset_ids
source_result_ids
issue_summary
```

API 建议拆分：

```text
POST /api/v1/projects/{projectId}/preview-versions
GET  /api/v1/projects/{projectId}/preview-versions
POST /api/v1/preview-versions/{versionId}/export
PATCH /api/v1/preview-versions/{versionId}/timeline
```

## 3. 建议完善

### 3.1 页面编号和页面清单需要统一

问题：

- `05-产品原型页面结构.md` 从 `页面 16：提示词模板` 后直接跳到 `26. 核心状态流转`。
- `11-完整产品页面流转与缺失页面补全.md` 当前 UI 画板已补页面列了 17 页，但 `ui-mockups/README.md` 列了 18 页，差异是“项目画像确认”。
- `05` 的必做页面清单缺少“项目画像确认”，但 UI 画板已经有。

建议：

1. 重排 `05` 的章节编号。
2. 三处页面清单统一为 18 页。
3. 将“生成结果审核”和“镜头成片确认”命名统一，建议面向用户叫“镜头成片确认”，API/技术文档可叫“生成结果审核”。

### 3.2 P0 / P1 范围需要重新标注

问题：

- 任务中心、模型配置、提示词模板、系统设置在 UI 中都比较完整。
- API 文档中任务中心接口很丰富，包括队列暂停/恢复、失败聚合、批量重试、优先级调整。
- 排期风险里仍写“优先 12 个核心页面”，但 UI 已经是 18 页。

建议：

1. 明确 P0 只做：任务列表、任务状态、失败原因、单任务重试、任务详情。
2. P1 做：失败分组、批量重试、成本筛选、任务日志。
3. P2 做：队列暂停/恢复、优先级调整、跨项目队列策略。
4. 模型配置 P0 只做供应商可用配置和连接测试；成本策略、能力标签、默认参数模板可 P1。

### 3.3 审计日志需要落表

现状：

- 技术方案和页面流转都提到审计日志。
- ERD 没有 `audit_logs` 表，API 也没有系统设置/审计查询接口。

建议补充：

```text
audit_logs
  id
  project_id nullable
  actor_id
  action
  target_type
  target_id
  before_snapshot
  after_snapshot
  request_id
  created_at
```

第一阶段至少记录：确认版本、删除资产、修改模型配置、导出成片、批量重试/取消任务。

### 3.4 失败案例库需要明确承载方式

现状：

- PRD、管理层文档和技术方案都提到失败案例沉淀。
- ERD 只有 `generation_results.failure_reason` 和 `review_records`，没有明确失败案例可复用结构。

建议：

1. 第一阶段先不新建独立失败案例库，只在 `generation_results` 增加 `is_failure_case`、`failure_category`、`failure_tags`。
2. 后续如要复用失败经验，再拆出 `failure_cases` 表。

### 3.5 模型密钥与供应商配置边界需要更具体

建议补充：

1. `model_providers.secret_ref` 对应密钥管理方案：环境变量、Vault、云密钥服务或本地加密。
2. API 响应永不返回密钥明文。
3. 模型测试接口只返回连通性、延迟、错误摘要。
4. `model_invocations.request_summary`、`response_summary` 应脱敏，避免保存完整版权文本或密钥。

### 3.6 验收标准建议从“一句话”拆成可测试清单

`02-产品需求文档-PRD.md` 的验收标准目前是一段完整描述，建议拆成表格：

| 模块 | 验收项 | 最低标准 |
|---|---|---|
| 项目/源内容 | 创建项目、确认 Source V1、确认 Profile V1 | 可推进到分析 |
| 文本 AI | 分析、剧本、版本确认 | JSON 校验、可编辑、可确认 |
| 资产 | 角色/场景/风格卡 | 可生成、编辑、确认、绑定 |
| 分镜 | Storyboard 镜头卡 | 可拆镜、改提示词、确认 |
| 生成 | 图像/视频候选 | 至少 1 个镜头完成图像和视频候选 |
| 审核 | 正式镜头 | 可设置通过版本并进入预览 |
| 后期 | 分集粗剪 | 可导出 MP4 或素材包 |
